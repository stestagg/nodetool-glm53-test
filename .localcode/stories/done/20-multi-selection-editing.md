## Description

Story 12 gave the canvas its first selection: one node at a time, moved by its title bar. Building real graphs means arranging them in batches — nudging a pipeline stage aside, deleting a clump that didn't work, setting the same parameter on five nodes at once — and doing each of those one node at a time is exactly the ceremony the Blender reference avoids. This story adds the selection layer over the gestures 12–14 delivered: shift-drag rectangle selection, multi-select moves, selection-wide delete, and the sidebar's behaviour when several nodes are selected — settling, as the vision's open question asks, how it chooses which fields to show.

The selection model:

- **Marquee**: shift-click-drag on the background draws a rectangle; every node inside or intersecting it joins the selection. Plain background drag stays panning (REQ-51) — the two background drags differ by Shift alone. The marquee selects nodes, never wires: edges are not selection targets, their fates ride with their nodes.
- **Toggle**: shift-click on a node adds it to, or removes it from, the current selection. Plain click selects that node alone and clears the rest; plain background click clears the selection entirely.
- Any non-empty selection opens the sidebar; emptying it closes it — story 14's open/close rule, unchanged.

**Multi-select move**: while more than one node is selected, dragging any non-port part of any selected node — a drag from a port stays 13's wire gesture — moves the whole selection, REQ-53's "anywhere if multi-selected": every selected node following the pointer for the duration of the drag, one commit landing where each rests. A node outside the selection, or a selection of one, keeps story 12's title-area drag: dragging it selects it alone and moves it by its title area, exactly as 12 moves a node. **Delete**: pressing Delete (or Backspace) with the canvas in focus removes every selected node, each with every edge attached to it cascaded — story 13's deferral, the same no-dangling-edges guarantee as one-node delete, applied to the multi-selection. While a sidebar or inline field has focus, the same keys edit text and never delete — the gesture lives on canvas focus, so a stray Backspace in a field cannot cost the selection its nodes.

The sidebar with several nodes selected shows a short header naming the selection — how many nodes — and then only the common parameter fields. A field is common when every selected node's type declares an input of that name which is scalar-possible by story 14's rule and unconnected on every selected node; everything else — labels, uuids, type references, connected or non-scalar inputs, fields only some of the nodes have — is not shown, because the sidebar edits stored values and only these are held in common. A common field shows its value only when every selected node holds the same one; when they differ it shows a distinct mixed state — the value area blank and marked with a visible marker (a "mixed" placeholder or similar), never a plain blank, because blank must mean unset-everywhere. Committing applies the typed value to every selected node; committing an empty field unsets it on every selected node, from the mixed state as from an unset one; Esc discards — story 14's commit rules inherited whole, with one scoping: a field left without anything typed into it commits nothing, discarding as Esc does, so a stray click away from a mixed field cannot unset the parameter on every node; the empty-means-unset rule rides a real edit (typed-then-cleared included), and Enter on an untouched mixed field stays a deliberate commit, clearing the parameter across the selection in one gesture. When the selection has no common fields at all, the sidebar says so plainly rather than sitting silently empty. Labels are deliberately not editable in a multi-selection: a label names one node, and a gesture that stamped one shared name across a multi-selection destroys the orientation labels exist for.

Unknown-typed placeholder nodes (12) take part in selection, multi-select moves, and multi-select delete — uuid-addressed operations need no type knowledge — but contribute no common fields, their ports unknown.

No new operation messages: the selection is a view-side convenience that fans out to the existing catalogue — a multi-select move sends the existing move operation once per node, a multi-select delete the existing delete operation once per node, a common-field commit the existing parameter edit once per node — the same precedent as 13's "rewiring is wire with replace semantics". The server neither knows nor cares that a selection existed; its error answers stand as in 11 and 14 — a stale tab's commit for an input that has since been wired is refused, the definition untouched, the connection usable. Selection itself is per-view state, like scroll position: a selection in one tab is not in another; the changes made through it are server state like any edit and appear everywhere.

While a run is on (16), marquee and toggling stay live — looking is not editing, and a selection is not an edit — while multi-select moves, multi-select deletes, and common-field commits go quiet with every other editing gesture.

Deliberately not here: align/distribute or snapping aids; copy-paste; box-selection of edges; group/subgraph packaging (23); the keyboard operability pass (22). Nothing is validated at edit time beyond the structural refusals 14 already makes — enforcement is compile time's (REQ-60, REQ-72).

## Definition of done

- Shift-click-drag on the canvas background draws a visible rectangle and every node inside or intersecting it joins a visible multi-selection; shift-click on a node toggles it in or out; plain click selects one node and clears the rest; plain background click clears the selection; the sidebar opens for any non-empty selection and closes when the selection empties. The marquee selects nodes only, never wires. (REQ-55, REQ-56)
- With several nodes selected, dragging any non-port part of any selected node moves the entire selection — a drag from a port stays 13's wire gesture — all selected nodes follow the pointer for the duration of the drag and one commit lands where each rests, positions recorded in node metadata through the existing server-applied operation path; a node outside the selection, or a selection of one, keeps story 12's title-area drag, dragging it selecting it alone and moving it by its title area, exactly as 12 moves a node. (REQ-53, REQ-12)
- Delete (or Backspace) with the canvas in focus and a multi-selection removes every selected node from canvas and definition together with every edge attached to any of them, leaving no dangling edges; with a sidebar or inline field in focus, the same keys edit text and never delete. (REQ-2)
- With several nodes selected, the sidebar shows a header naming the selection and only the common parameter fields — an input declared scalar-possible by every selected node's type and unconnected on every one of them — the value shown only when all selected nodes hold the same value, a distinct mixed state otherwise — a visible marker in the field, never a plain blank, since blank must mean unset-everywhere; committing applies the value to every selected node, committing an empty field unsets it on every one (from the mixed state too), Esc discards — and a field left without anything typed into it commits nothing, discarding as Esc does, so a stray click away from a mixed field cannot unset the parameter on every node; with no common fields the sidebar says so plainly; no label editing and no uuid/type block in the multi-selection sidebar. (REQ-56, REQ-47)
- Marquee, toggle, and clearing the selection stay available while a run is on; multi-select moves, multi-select deletes, and common-field commits are inert in the UI, and any edit operation arriving while running is rejected by the server like every other. (REQ-24, REQ-25)
- The server receives no new message kinds: a multi-select move, delete, or common-field commit arrives as the existing per-node operations, applied and pushed as in 12–14; a parameter edit arriving for a since-connected input is answered with 14's error, the definition untouched, the connection usable. Selection is per-view state: a second tab shows the same graph, not the same selection, and a change made through a selection in one tab appears in the other. (REQ-2, REQ-45)
- Focused tests cover the story's new logic, which is all view-side: the selection model, the common-field rule — same input name, scalar-possible on every selected node, unconnected on every one — the mixed state, and the one-operation-per-node fan-out of move, delete, and commit, an empty commit unsetting on every one. The per-node operations the fan-out sends are 12–14's, already tested server-side — this story adds no message, no branch, and no second path to them. Reaching the browser-side logic takes a UI test runner: if the check set DEVELOPMENT.md documents has none yet, this story adds the smallest one that does. The workspace builds and passes `cargo test` and `cargo clippy` cleanly, with the UI build part of the check set DEVELOPMENT.md documents.
- The visible proof, run per DEVELOPMENT.md: drop a row of nodes, marquee three, drag one of them by any non-port part and watch all three travel together; shift-click a fourth in and out of the selection; select two nodes sharing a scalar input, type a value into the sidebar field and see it land on both, then set one to a different value first and see the mixed state — the field marked, never blank — before committing; click into that mixed field and click away without typing and see every value survive; press Delete with three selected and see the nodes and their wires go together, then focus a sidebar field, Backspace into it, and see the text edited and nothing deleted; reload and see the graph with the selection gone; start a run and check the marquee still selects while a multi-select drag does nothing.

## Comments

- 2026-09-16 — Scope seams: no additions to story 11's message catalogue — the selection fans out to 12's move, 13's delete, and 14's parameter edit, one operation per node, the precedent 13 set with rewiring. Multi-select delete was 13's explicit deferral here; the common-fields sidebar was 14's; 16 reserved selection as live while running. Copy-paste, alignment aids, edge marquee, and group packaging (23) are out; keyboard operability of these gestures is 22's pass. (REQ-74)
- 2026-09-16 — UX calls settled here, answering the vision's open question on the multi-selection sidebar: common fields only, chosen by a rule the browser reads off the listing — same input name everywhere, scalar-possible everywhere, unconnected everywhere — so core never branches on what a node is (REQ-73) and a plugin's nodes join multi-selections for free by declaring scalar ports (REQ-38). No multi-selection rename, per the description. The mixed state is shown rather than silently committing blank or displaying one node's value as if shared — either would lie about what a commit would do. Empty-commit-unsets is inherited from 14 so clearing a multi-selection's parameter is one gesture, consistent with empty-means-unset everywhere else.
- 2026-09-16 — Why no new messages: the user-visible behaviour — one drag, one Delete, one field commit — is identical either way, and per-node operations keep one mechanism for each edit kind (REQ-2); whole-definition pushes (12) make the fan-out cheap for a local single-user tool, and selection stays per-view state so nothing about it needs the server's participation.
- 2026-09-16 — Review calls, recorded so they hold: the mixed state is a visible marker in the field (a "mixed" placeholder or similar), never a plain blank — blank must mean unset-everywhere, so mixed and unset-everywhere could not otherwise be told apart and neither the state nor the criterion could be verified. Leaving a field nothing was typed into commits nothing: 14's blur-commit is harmless only while a field holds the value it would re-commit, and the mixed state is the first blank field with real values behind it, so a stray click away must not unset the parameter on every selected node. Enter on an untouched mixed field stays a deliberate commit — clearing the parameter across the selection in one gesture, the reason empty-commit-unsets was inherited. Delete/Backspace is scoped to canvas focus because multi-selection is where a stray keypress costs N nodes rather than one. A multi-select move's drag boundary: from a port stays 13's wire gesture; a node outside the selection, or a selection of one, moves exactly as 12 moves a node. "Multi-select" is this story's word for the selection set throughout; "group" stays 23's — a node backed by a subgraph. The story's tests run in a UI test runner added to DEVELOPMENT.md's check set if none is there yet — the first story whose additions live entirely in the browser, so the smallest runner that reaches the browser-side logic is the right cost.
